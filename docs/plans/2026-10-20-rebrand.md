# Rebrand: gamification for any website

Same name, same packages. What changes is what dopaminejs says it is, and the few things a
site needs before that claim is true.

## The line

> **Gamification for any website.** XP, streaks, achievements, certificates and confetti,
> from one script tag or one import.

Who it is for, in order: course and training sites, blogs and docs, product onboarding,
community and habit sites, web apps, and games last (still supported, no longer the lead).

The example that has to work end to end: a visitor finishes a video, gets XP, an
achievement and a certificate, and confetti goes off. Today that takes a `RewardSystem`, a
`ParticleSystem`, a `GameUI`, a bundler and wiring code, and there is no certificate at all.

## What is in the way today

- **Words.** The README already leads with web apps, but the GitHub topics say
  `game-development` and `html5-games`, the themes package says "Cyberpunk, Neon, Retro",
  five plugin descriptions say nothing about the web, and the homepage URL is empty.
- **No script tag build.** The core ships ESM and CJS only (`packages/dopaminejs/package.json`
  has no `unpkg` or `jsdelivr` field). A blog or a static site with no bundler cannot use it.
- **No one-call celebration.** Confetti needs `new ParticleSystem()` and a call with
  coordinates. There is no `celebrate('complete')`.
- **Game words in the API.** `recordGame`, `GameUI`, `showNearMiss` ("CLOSE CALL!"), and
  `showSummary` hardcodes "Game Over" (`GameUI.js:339`). #39 makes three of those strings
  configurable; this plan adds the rest.
- **No certificate.** Nothing renders a completion certificate a visitor can keep.
- **No way to wire it without JavaScript.** A content editor cannot say "this video gives
  50 XP when it ends" in the HTML.

## Phases

Each phase is one ticket and one PR unless it says otherwise. Nothing here breaks 2.x.

### 1. Words (no code)

- README: the line above, the use-case list reordered as above, the video and certificate
  example as the first code block once phases 2 to 4 exist (until then, the current quick
  start stays).
- `description` and `keywords` in every `packages/*/package.json`. Themes: describe the
  look ("light, dark and high contrast themes" etc.) from what the CSS actually holds.
- GitHub: description to the line; topics drop `game-development` and `html5-games`, add
  `gamification`, `engagement`, `confetti`, `certificates`, `achievements`, `no-build`;
  homepage URL to the demo once phase 6 is live.
- Wiki Home and sidebar, and `CLAUDE.md` "What this is".

Can start now. Independent of everything else.

### 2. Script tag build

- An IIFE build of the core, `dist/dopamine.global.js`, exposing `window.Dopamine`, plus the
  existing `style.css`. `unpkg` and `jsdelivr` fields point at it.
- A size-limit entry for it, budget from the measured number (same rule as #41).
- README quick start gets a no-build tab:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/dopaminejs/dist/style.css">
<script src="https://cdn.jsdelivr.net/npm/dopaminejs/dist/dopamine.global.js"></script>
```

- The README snippet pins an exact version and carries `integrity` and `crossorigin`
  attributes. The release workflow prints the SRI hash of the published file so the README
  and release notes can quote it.
- A test that loads the built file in jsdom with no module loader and finds the globals.

### 3. Moments API

- `celebrate(preset, options)`: one call that plays confetti, a toast and an optional sound,
  centred on the viewport or on an element. Presets: `complete`, `milestone`, `streak`,
  `certificate`. Honours `prefers-reduced-motion` (no particles, the toast still shows), which
  `ParticleSystem` already detects.
- `rewards.recordActivity(id, { score })` as the documented name, with `recordGame` kept as
  an alias. `RewardUI` exported as an alias of `GameUI`. Both names stay through 2.x.
- The `text` option from #39 extended to `showSummary` ("Game Over" becomes configurable)
  and the remaining fixed strings.
- Public API snapshot and types updated in the same PR.

Starts after #39 merges, because it builds on that text option.

### 4. Certificate

- `showCertificate({ title, recipient, date, issuer, logo })`: a modal card with a
  "Download" button (PNG drawn on a canvas, no dependency) and "Print". Every field is set
  as text; `logo` follows the `safeIcons` rules from #39.
- `celebrate('certificate', { certificate: {...} })` opens it after the confetti.
- Removes its DOM and listeners in `destroy()`, with a test (repo rule).
- Themeable through the existing CSS variables.

Starts after phase 3.

### 5. HTML attributes

Opt in with `Dopamine.auto()` (or `data-dopamine-auto` on the script tag). Then:

```html
<video src="intro.mp4" data-dopamine-on="ended" data-dopamine-xp="50"
       data-dopamine-achievement="watched-intro"
       data-dopamine-celebrate="certificate"
       data-dopamine-certificate-title="Intro course"></video>

<button data-dopamine-on="click" data-dopamine-xp="10">Mark lesson done</button>
<article data-dopamine-on="read" data-dopamine-xp="5">...</article>
```

- Events: `click`, `ended` (media), `submit` (forms), `read` (scrolled to the end, via
  IntersectionObserver on a sentinel), `visible`.
- A `MutationObserver` picks up elements added later. Everything is removed on `destroy()`.
- Achievement ids and attribute values are untrusted input: own-property lookups (repo rule)
  and text-only rendering.

Starts after phases 2 and 3.

### 6. Demo site and recipes

- One static page on GitHub Pages, built with the script tag only, with three sections: a
  course lesson (video, XP, certificate, confetti), a blog post (read to the end, streak),
  a docs tutorial (finish the steps, badge). It is also the homepage URL in phase 1.
- Recipes in the wiki, one page each: video completion, course certificate, reading streak,
  onboarding checklist, form completion, React, Vue.

Starts after phase 5.

### 7. Release

One minor release (2.5.0 or whatever is next) with phases 2 to 5, release notes leading
with the video and certificate example, then the GitHub description and homepage switch.

## Order

Phase 1 now. Phases 2 and 3 in parallel once #39 merges. Phase 4 after 3. Phase 5 after
2 and 3. Phase 6 after 5. Phase 7 last. At most four in flight.

## Not in this plan

- Renaming the package or the repository.
- Removing any game API. `Game`, `Scene`, the engine and the game-flavoured helpers stay
  exported through 2.x.
- A backend. Progress stays in the browser (or the storage the site passes in). Server-side
  certificates and verification links are a later question.

## Decisions for Arnel

1. **Demo hosting:** GitHub Pages under BaryoDev (my recommendation: free, ships with the
   repo) or a page on baryo.dev.
2. **Certificate download:** PNG only (recommended, no dependency) or PNG plus PDF (PDF
   needs either a dependency or a lot of hand-written code).
3. **3.0:** move the game-only helpers (`showNearMiss`, `showCombo`, `showLuckyMoment`,
   `showSummary`, the game sounds) out of the core into a `dopaminejs-plugin-games`, or keep
   them in the core. Not needed for this plan, but phase 3's naming should know the answer.
